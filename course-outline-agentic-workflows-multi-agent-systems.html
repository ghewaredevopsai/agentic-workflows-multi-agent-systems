Agentic Workflows & Multi-Agent Systems

Build, Evaluate and Operate Multi-Agent Systems in Production
3 Days · Hands-on | Advanced | 9 modules · 48 labs · capstone | 45% theory · 55% labs | Trainer: Rajesh Gheware
Day 1 — The Agent Loop: Reasoning, Memory & State

Module 1 · Agents vs. Multi-Agent Systems

  • LLM vs. agent — reasoning loops, action loops, autonomy; agents vs. chatbots vs. RAG
  • The four building blocks: LLM (brain) · Memory (state) · Tools (actions) · Planning
  • Patterns: single agent, multi-agent, supervisor/worker — and the coordination tax of each extra agent
  • The decision rubric you take away: when one agent is enough, when to split, when to build neither
  • LLM limitations that create the need for agents in the first place
  • Fast on-ramp: LangChain 1.x essentials and create_agent — enough to build, not a tour

Module 2 · Agentic Planning & Reasoning

  • Architectures compared on identical tasks: Chain-of-Thought, ReAct, Tree-of-Thought, Reflection
  • Task decomposition into sub-goals an agent can finish; dependency-aware ordering
  • Re-planning vs. blind retry — transient failure or wrong plan?
  • Stop conditions, step budgets and loop detection — the most common production failure
  • Where each pattern earns its cost: quality vs. tokens vs. latency, measured not asserted

Module 3 · LangGraph: Stateful Agent Workflows

  • Agent state made explicit: a declared schema you can print, assert on and store — not text implied by a conversation
  • StateGraph: nodes as plain functions, edges as the dependency order, and control flow you can unit-test without a model
  • Conditional routing and cycles — branching on state, looping back, and the step budget that stops a runaway
  • State reducers: declaring how a field merges, and why parallel nodes make it mandatory
  • Checkpointing — persistence, resume after restart, time travel, and the audit trail that falls out of it
  • Human-in-the-loop: interrupt points and approval gates placed on the branch that needs one
Day 1 Labs (notebooks: M1 · M2 · M3) — the agent loop by hand · four building blocks · tool descriptions, measured · Chain-of-Thought · ReAct · Tree-of-Thought · Reflection · first StateGraph · conditional routing · cycles & retry · checkpointing · human-in-the-loop · build your baseline eval set & pass rate — the number every later milestone is measured against
Day 2 — Tools, MCP, Orchestration & Agentic RAG

Module 4 · Tool Calling & MCP MCP

  • Why tools matter; custom tool development, multi-tool orchestration, function-calling agents
  • Tool descriptions are instructions — measured against an eval set you build, not asserted
  • MCP architecture: servers, tools, resources, prompts, transports; why a protocol beats bespoke integrations
  • MCP client configuration and workflows; bridging MCP servers into LangChain agents
  • Enterprise MCP use cases and ecosystem discovery
  • Injection arriving through tool results; what a tool must return when it fails

Module 5 · Multi-Agent Collaboration & Orchestration

  • Supervisor/worker — rule-based and LLM-routed — plus peer-to-peer and agent handoffs
  • Task decomposition and distribution; aggregation and conflict resolution between agents
  • Parallel execution, multi-branch graphs, conditional routing, error handling, retry and backoff
  • Cost of collaboration: a 5-agent system runs 3–10× the tokens of one agent — per-agent model routing, cheap model routes, strong model reasons
  • Human-in-the-loop as an orchestration mechanism: interrupt points, approval gates, timeout, escalation
  • Measure the graph against your own Day 1 single agent — quality, cost, latency; and when the honest answer is "don't"
  • Production patterns: specialisation, fallback, termination and runaway-loop control

Module 6 · Agentic RAG

  • From RAG pipeline to retrieval as a tool the agent chooses to call, repeatedly, with intent
  • Embeddings, ChromaDB collections and metadata, document loading, chunking, similarity-search strategy
  • Query processing, multi-hop retrieval, and re-querying when the first result is inadequate
  • Response generation with citations; grounding discipline and refusing when unsupported
  • RAG-powered agents with memory — the retriever inside a conversational, tool-using agent
  • Evaluating retrieval separately from generation — faithfulness vs. relevance

Day 3 — Evaluation, Safety & AgentOps

Module 7 · Multi-Agent System Evaluation

  • Why demo-driven development fails here: same input, twice, two different runs
  • Extending the Day 1 eval set — representative, edge and adversarial cases; outcome vs. trajectory assertions
  • Tracing agent reasoning — traces, spans, generations; tool-call visibility; latency breakdown
  • Scoring in LangFuse: feedback collection, scores, A/B testing prompts on real traffic
  • Prompt management and versioning as an evaluated, rolled-out artifact, not an edit in place
  • Cost analysis: tokens and cost per step, per agent, per run — and cost/latency as release gates, not reports
  • Locating the failure: which agent, tool or retrieval step actually caused it

Module 8 · Safety & Guardrails

  • Prompt-injection detection and input sanitisation; jailbreak resistance; red-teaming your own system
  • Output validation and structured-output contracts enforced between every hop
  • Guardrails integration into the agent graph — where a check belongs and what it costs
  • MCP tool governance — scopes, least privilege, blast radius; what an agent may call unattended
  • Human-in-the-loop as a safety control: approval gates before any write or irreversible action
  • Safety monitoring: what to alarm on for a system that can be wrong without erroring
  • Data boundaries — PII, secrets, and what must never enter a prompt, a trace or a vector store

Module 9 · Deployment & AgentOps

  • FastAPI + LangGraph as a service: async handling, streaming responses, error handling, validation
  • Health checks and readiness probes; secrets management; the production readiness checklist
  • Containerise and deploy to Kubernetes: Deployments, Services, Ingress, Secrets, HPA, resource limits
  • OpenTelemetry — the three pillars, custom spans, OTLP and the collector
  • Production observability end to end: traces, metrics, structured logging, cost dashboards, alerting
  • Scaling, debugging and the on-call runbook for an agentic service
