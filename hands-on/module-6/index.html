Module 6 — Agentic RAG

Day 2 hands-on · five labs, intermediate to advanced
One case file throughout · self-checked · solutions provided

How these labs work. Fill every BLANK, then run the Self-check cell under each section. It prints [PASS], [FAIL] or [TODO], and the last cell prints your Score.

Self-checks assert on the objects you built — a chunked Document, a Chroma collection, a bound @tool, a compiled StateGraph, a parser. None of that needs the gateway, so your score never depends on a live model. Cells marked Run it for real do call the sandbox model — if it is unreachable they print how to fix it rather than crashing, so Run All is always safe on an untouched notebook.

A corpus, not a ledger — two short operating documents about the same payments, which the agent has to go and read. Retrieval runs on a real Chroma collection, embedded by a thirty-line Embeddings class you can read line by line: the sandbox has no egress, and chromadb's default embedding function wants an 80 MB download. Everything else — chunking, floors, metadata filters, citations, the metrics — is identical whatever computes the similarity.

Lab 6.1 — A Retriever You Can Inspect

Cut a document two ways and watch one of them put an answer permanently out of reach.

  • Split with MarkdownHeaderTextSplitter, so a rule keeps the exception that qualifies it
  • Write an Embeddings class and index the corpus in Chroma
  • Watch top-k return four confident chunks from a corpus that has nothing — then choose the floor
  • Scope with a metadata filter — a filter is also an access control

Lab 6.2 — Retrieval as a Tool the Agent Chooses

Half the questions in the set need no corpus at all. A pipeline retrieves for all of them.

  • Wrap the retriever in a @tool — and write the description the model actually reads
  • Offer it beside the ledger tool with bind_tools, and let the model decide
  • Price always-retrieve: the tokens, and the noise it puts next to the real context
  • Rewrite the user's words into the corpus's vocabulary

40 minAdvanced

Lab 6.3 — Adequacy, Re-querying and Multi-Hop

The loop a pipeline cannot have: judge your own retrieval, then ask again with what it taught you.

  • An adequacy test that can actually say no
  • Build retrieve → judge → re-query as a compiled StateGraph
  • Re-query with a reason code the first hop taught you
  • A hop budget, a repeat detector, and ‘I could not find it’ as a real outcome
2 blanks · 19 checks · solution: solutions/lab-6-03-adequacy-and-multi-hop.ipynb
40 minAdvanced

Lab 6.4 — Citations Bound to Spans, and Refusing

A citation that names a document proves nothing. A span is checkable by string comparison.

  • Declare a citation as a Pydantic schema the model has to fill
  • Pick the parser that actually rejects a bad one — one of the two does not
  • Bind each claim to the exact characters that support it, and drop the ones that cannot be bound
  • Refuse when the corpus cannot answer — structurally, and then in the prompt
4 blanks · 26 checks · solution: solutions/lab-6-04-citations-and-refusing.ipynb
40 minAdvanced · challenge

Lab 6.5 — Challenge: Score the Two Halves Apart

A right answer from the wrong evidence passes every demo you will ever run.

  • Label an eval set, measure recall@k and precision@k, and choose k with the numbers
  • Measure faithfulness and answer relevance with no labels at all
  • Put a run in the 2×2 and read off which half to fix
  • Meet the limits of an exact-match faithfulness score — on purpose
