Module 9 — Deployment & AgentOps

Day 3 hands-on · five labs, intermediate to advanced
No cluster required · self-checked · solutions provided

How these labs work. Fill every BLANK, then run the Self-check cell under each section. It prints [PASS], [FAIL] or [TODO], and the last cell prints your Score.

You write real framework code. A FastAPI app and its routes, Pydantic request and response contracts, LangChain tools and an agent behind the boundary, and Kubernetes manifests as Python dicts. The self-checks assert on the objects you built — a route table, a schema, a compiled tool, a manifest — so they are deterministic.

Your score never depends on a live model. Only cells marked Run it for real call the sandbox model — if it is unreachable they print how to fix it rather than crashing, so Run All is always safe on an untouched notebook.

Nothing graded here needs a cluster. A Kubernetes manifest is JSON and YAML is a surface syntax over it, so the linting is a predicate over a Python dict; the kubelet's probe loop is twenty lines. kubectl apply --dry-run=server, your own namespace and the tracing backend live only in the Run it for real cells — and a full starter manifest ships beside these notebooks as app-deploy-example.yaml.
