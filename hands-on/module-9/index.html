Day 3 hands-on · one lab, advanced
Nothing graded needs a cluster · self-checked · solution provided

How these labs work. Fill every BLANK, then run the Self-check cell under each section. It prints [PASS], [FAIL] or [TODO], and the last cell prints your Score.

You write the manifests that ship a real service. Kubernetes objects as Python dicts — a ConfigMap, a PVC, a Deployment, a Service and an Ingress — and the self-checks assert on the objects you built, so they are deterministic.

Your score never depends on the cluster. Only cells marked Run it for real touch your namespace — if it is not set they print what to do instead of crashing, so Run All is always safe on an untouched notebook.

Nothing graded here needs a cluster. A Kubernetes manifest is JSON and YAML is a surface syntax over it, so every rule is a predicate over a Python dict and runs offline in milliseconds. The whole design is graded before anything is applied; applying it comes after, in the Run it for real cells.

Lab 9.1 — Deploy the FrontDesk Service

Three days of agents in a notebook. This one puts a multi-agent service on a cluster, in your namespace, on your hostname, and asks it a question.

  • Read what your namespace allows, and what it can reach
  • Make the five choices those limits force — including the one that has already broken this app once
  • Lint the whole manifest set offline, before anything is scheduled
  • Apply them, wait for the rollout, and get a grounded answer out of the running service
  • Read your own trace back out of Tempo — the only evidence that telemetry works
