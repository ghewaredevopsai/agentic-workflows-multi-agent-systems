Module 7 — Multi-Agent System Evaluation

Day 3 hands-on · five labs, intermediate to advanced
One case file throughout · self-checked · solutions provided

How these labs work. Fill every BLANK, then run the Self-check cell under each section. It prints [PASS], [FAIL] or [TODO], and the last cell prints your Score.

Your score never depends on a live model. Graded cells are plain Python. Cells marked Run it for real do call the sandbox model — if it is unreachable they print how to fix it rather than crashing, so Run All is always safe on an untouched notebook.

Nothing is built today. These labs measure what the last two days produced. The stand-in agent is a seeded RNG, so the statistics are real statistics computed offline for nothing; the tracer is yours, written by hand, and the Run it for real cells measure the sandbox model's actual variance and map your span tree onto LangFuse's fields.

Lab 7.1 — Non-Determinism, Measured

On ten cases, even a 35-point improvement cannot be established. Find out why, and what fixes it.

  • Watch the same system score differently run after run
  • Compute the range a single run was drawing from
  • Decide whether a difference between two versions is real
  • Discover what size of win your eval set can detect at all

Lab 7.3 — Outcome and Trajectory Assertions

Five recorded runs. Four pass every outcome check. One of them tried to release a sanctioned payment.

  • Write the outcome assertions everybody writes
  • Find the run they all pass and should not
  • Add trajectory assertions and watch two runs turn red
  • Grade representative, edge and adversarial cases separately

Lab 7.4 — Locating the Failure

Six failed runs. Without a trace all six are “the agent hallucinated”. Five of them are not.

  • Walk an ordered attribution ladder to the step that caused it
  • Handle the run with three things wrong — the first one is the cause
  • Count the spend wasted downstream of each failure
  • Let the totals choose which fix comes first

Lab 7.5 — Challenge: The Release Gate

Four candidates, three thresholds agreed in advance, and one version that is provably better and blocked.

  • Summarise each candidate as a mean and a range
  • Build a gate that fails a build, not a dashboard nobody reads
  • Find the conservative test that lets a bad version through
  • Produce a ship / do-not-ship decision with reasons
