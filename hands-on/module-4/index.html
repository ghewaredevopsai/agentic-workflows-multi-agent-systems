Module 4 — Tool Calling & MCP

Day 2 hands-on · five labs, intermediate to advanced
One case file throughout · self-checked · solutions provided

How these labs work. Fill every BLANK, then run the Self-check cell under each section. It prints [PASS], [FAIL] or [TODO], and the last cell prints a Self-check tally. The score line is feedback, not a grade.

You write real LangChain and MCP code in every lab. The Self-check cells assert on the objects you build — a @tool, an argument schema, a ToolMessage, an mcp.types.Tool — so they are deterministic and do not need the model. Cells marked Run it for real put your code in front of the sandbox model; if it is unreachable they print how to fix it rather than crashing, so Run All is always safe on an untouched notebook.

The same case file as Day 1 — payment exceptions on a small synthetic ledger, now reached through tools the agent chooses, and then through tools it did not write. Labs 4.4 and 4.5 need no model and no network for a single graded check: the MCP server, the client and the bridge all run in this process, and one cell launches a server as a real subprocess over real pipes.
