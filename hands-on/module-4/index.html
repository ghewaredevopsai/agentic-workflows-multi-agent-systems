Module 4 — Tool Calling & MCP

Day 2 hands-on · five labs, intermediate to advanced
One case file throughout · self-checked · solutions provided

How these labs work. Fill every BLANK, then run the Self-check cell under each section. It prints [PASS], [FAIL] or [TODO], and the last cell prints a Self-check tally. The score line is feedback, not a grade.

You write real LangChain and MCP code in every lab. The Self-check cells assert on the objects you build — a @tool, an argument schema, a ToolMessage, an mcp.types.Tool — so they are deterministic and do not need the model. Cells marked Run it for real put your code in front of the sandbox model; if it is unreachable they print how to fix it rather than crashing, so Run All is always safe on an untouched notebook.

The same case file as Day 1 — payment exceptions on a small synthetic ledger, now reached through tools the agent chooses, and then through tools it did not write. Labs 4.4 and 4.5 need no model and no network for a single graded check: the MCP server, the client and the bridge all run in this process, and one cell launches a server as a real subprocess over real pipes.

Lab 4.1 — OpenCode to Jira, over MCP

Watch a real agent reach a real Jira through MCP, then count what the grant cost you.

  • Talk to a live MCP server by hand — initialize, then tools/list
  • Grant an agent access to Jira by writing four lines of JSON
  • Watch opencode triage a payment exception and raise the ticket for it
  • See what it cost — in tools, in context and in audit trail

Lab 4.2 — Ask Your Traces

Add a second server to the agent from 4.1, then get answers out of your observability data without writing a query.

  • Extend Lab 4.1's opencode.json — one agent, two servers
  • Find your slowest step, your step ratios, and which tools actually get called
  • Triage errors and check for regressions by asking in English
  • Leave with a prompt library you will use for real on Day 3

Lab 4.3 — Your Own Repos, Your Own Identity

A third server on the same agent — and the first credential that is yours, so the audit trail finally names a person.

  • Make a read-only fine-grained token, and see why scope beats config
  • Prove the token is yours with get_me before trusting it
  • Extend the config again — Jira, Langfuse and GitHub on one agent
  • Review queues, release notes and repo onboarding, by asking
walkthrough · nothing to fill in · bring a GitHub account
35 minAdvanced

Lab 4.4 — Ask Your App What It Just Did

Your agent works. But did it read the policy, or recall one? The answer is not in the answer — it is in the trace.

  • Trace a payment-exception agent with one line of LangChain callback
  • Ask which tools it called and how many model round-trips it cost
  • Turn those questions into assertions you can fail a build on
  • Catch a prompt regression that leaves the answer looking fine

Lab 4.5 — Challenge: The Bridge, and What Comes Back Through It

Forty lines bridge MCP into an agent. The hard part is the prose that arrives with it.

  • Adapt MCP specs into StructuredTool objects an agent can be handed
  • Audit descriptions you did not write, and refuse the ones you cannot
  • Stop an instruction hidden in a legitimate tool result
  • Build the gate no tool result can talk past
